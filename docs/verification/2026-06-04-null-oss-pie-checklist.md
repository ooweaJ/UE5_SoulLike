# 2026-06-04 NULL OSS PIE 멀티플레이 검증 체크리스트

## 목적

Steam OSS 전환 전에 NULL OSS/PIE 환경에서 게임플레이 동기화 문제가 재현 가능한지 확인한다.

검증 목표는 "대충 잘 보인다"가 아니라 서버와 클라이언트 화면에서 같은 액션 상태, 같은 타이밍, 같은 결과가 관찰되는지 확인하는 것이다.

## 기본 테스트 환경

- Engine: Unreal Engine 5.7
- Online Subsystem: NULL
- Net mode: Listen Server 기준
- 플레이 인원: PIE 2 Players 우선
- 맵: 현재 `MainWorld` 또는 AI/플레이어 전투가 가능한 테스트 맵
- 캐릭터: 플레이어 캐릭터 2개 중 최소 1개, AI는 Grux 또는 `ANS_MontagePlayRate`가 들어간 AI

## 공통 기록 항목

각 테스트마다 아래 내용을 남긴다.

- 날짜
- 맵 이름
- PIE 플레이어 수
- 서버 캐릭터 / 클라이언트 캐릭터
- AI 종류
- 테스트한 액션
- 서버 화면 결과
- 클라이언트 화면 결과
- 실패 시 증상
- 관련 로그 또는 스크린샷/녹화 여부

## 1. 기본 연결/세션 확인

### 확인 항목

- PIE 2 Players 실행 시 서버와 클라이언트가 같은 월드에 들어오는가.
- 양쪽 플레이어가 서로 보이는가.
- 이동이 상대 화면에 반영되는가.
- 공격 입력이 상대 화면에 보이는가.

### 통과 기준

- 두 플레이어가 같은 맵에서 서로 관찰된다.
- 서버와 클라이언트 모두 상대 이동을 볼 수 있다.
- 명확한 접속 실패, 맵 불일치, 캐릭터 스폰 실패가 없다.

## 2. StateComponent 상태 복제 확인

### 배경

2026-06-04에 `UStateComponent::Type` 복제를 추가했다.

### 확인 항목

- 기본 공격 시 서버/클라이언트 모두 캐릭터가 Action 상태로 전환되는가.
- 공격 종료 Notify 이후 Idle 상태로 돌아오는가.
- 피격 시 Hitted/Dead 계열 상태가 양쪽에서 일관되게 보이는가.
- 회피 또는 스텝백 액션 중 다른 입력이 잘 막히는가.

### 통과 기준

- 서버와 클라이언트에서 액션 중복 입력, 상태 고착, Idle 미복귀가 발생하지 않는다.
- 한쪽 화면에서만 공격 중이고 다른 쪽은 Idle로 보이는 증상이 없다.

### 주의할 점

- 현재 `StateComponent`는 복제되지만, 모든 상태 변경 함수가 서버에서만 호출된다는 보장은 아직 부족하다.
- 클라이언트 로컬에서 상태를 먼저 바꾸는 흐름이 있으면 추가 정리가 필요하다.

## 3. AI 몽타주 속도 변경 동기화 확인

### 배경

2026-06-04에 `ANS_MontagePlayRate`가 AIController를 직접 찾던 구조를 제거하고, `AAIBaseCharacter::TimedMontagePlayRate` 복제 상태로 변경했다.

### 확인 항목

- `ANS_MontagePlayRate`가 들어간 AI 공격 몽타주가 실제로 발동되는가.
- 속도 변경이 발동했을 때 서버 화면에서 AI 몽타주가 느려지는가.
- 같은 순간 클라이언트 화면에서도 AI 몽타주가 느려지는가.
- Notify 종료 후 양쪽 화면에서 재생 속도가 정상으로 돌아오는가.
- 속도 변경이 발동하지 않은 경우 양쪽 화면 모두 정상 속도로 유지되는가.

### 통과 기준

- 속도 변경 발동 여부가 서버와 클라이언트에서 다르게 보이지 않는다.
- 속도 변경 구간 시작/종료가 양쪽 화면에서 눈에 띄게 어긋나지 않는다.
- Notify 종료 후 AI가 계속 느린 속도로 남아 있지 않는다.

### 실패로 볼 증상

- 서버 화면만 느려지고 클라이언트 화면은 정상 속도다.
- 클라이언트 화면만 느려진다.
- 속도 변경 종료 후 한쪽 화면에서만 계속 느리다.
- 공격 판정 타이밍이 서버/클라이언트 화면에서 다르게 보인다.
- `CurrentData.AnimMontage`가 비어 있어 속도 변경이 적용되지 않는다.

## 4. Anim Notify 기반 이동 확인

### 배경

`ANS_MoveToTarget`는 Notify Tick에서 `SetActorLocation`을 직접 호출한다.

### 확인 항목

- AI가 타겟으로 이동하는 Notify 구간에서 서버/클라이언트 위치가 크게 어긋나는가.
- 클라이언트 화면에서 순간이동, 위치 보정, 끊김이 보이는가.
- 이동 종료 위치가 서버와 클라이언트에서 같은가.

### 통과 기준

- AI 위치가 서버/클라이언트 화면에서 큰 차이 없이 보인다.
- 이동 종료 후 위치 보정이 반복되지 않는다.

### 예상 리스크

- 이 구조는 캐릭터 무브먼트 네트워크 보정과 충돌할 수 있으므로, 이후 별도 리팩터링 대상이다.

## 5. 아이템/장비/현재 액션 데이터 확인

### 배경

현재 `AItem`, `UEquipComponent::SelectItem`, `AItem::CurrentData`는 아직 복제 구조가 부족하다.

### 확인 항목

- 서버와 클라이언트에서 같은 무기/아이템이 장착되어 보이는가.
- 같은 공격 입력에 같은 몽타주가 재생되는가.
- 콤보 진행 시 서버/클라이언트가 같은 콤보 단계로 보이는가.
- 공격 판정이 서버 기준으로만 적용되는가.

### 통과 기준

- 장착 아이템 외형과 공격 몽타주가 화면별로 다르게 보이지 않는다.
- 클라이언트에서 때린 것처럼 보여도 서버 판정상 데미지가 다르게 들어가는 상황을 기록할 수 있다.

### 다음 설계 후보

- `EquipComponent::SelectItem` 복제
- `AItem` 복제 여부 결정
- `CurrentData` 자체 복제 대신 액션 ID/GameplayTag/몽타주 섹션/시작 시간만 복제

## 6. Spearman 투사체 확인

### 확인 항목

- Spearman 스킬 몽타주가 서버/클라이언트에서 모두 보이는가.
- 투사체가 양쪽 화면에서 생성되는가.
- 투사체 위치와 충돌 결과가 서버 기준으로 일관되는가.

### 통과 기준

- 투사체가 한쪽 화면에만 보이지 않는다.
- 데미지 결과가 서버 기준으로 한 번만 적용된다.

## 7. 로그/디버그 참고

필요 시 PIE 콘솔에서 아래 항목을 사용한다.

- `stat net`: 네트워크 상태 확인
- `showdebug animation`: 애니메이션 상태 확인
- `p.NetShowCorrections 1`: 위치 보정 확인
- `Net PktLag=100`: 지연 상황 테스트
- `Net PktLoss=5`: 패킷 손실 상황 테스트

지연/손실 테스트는 기본 검증이 통과한 뒤 진행한다.

## 우선 검증 순서

1. PIE 2 Players 기본 연결 확인
2. 플레이어 이동/기본 공격 관찰
3. `StateComponent` 상태 전환 확인
4. AI 몽타주 속도 변경 확인
5. AI Notify 이동 보정 확인
6. 장비/아이템/콤보 동기화 확인
7. Spearman 투사체 확인

## 현재 결론

다음 실제 테스트의 1순위는 AI 몽타주 속도 변경이다.

코드상 연결은 유지되어 있으나, 해당 AI 몽타주 애셋에 `ANS_MontagePlayRate` Notify State가 실제로 들어 있어야 실행된다. 에디터에서 Notify 존재 여부를 먼저 확인해야 한다.
