# 2026-06-12 작업 로그

## 작업 목표

- `docs/architecture/2026-06-12-unified-action-layer.md`의 통일 액션 레이어 설계를 기준으로 1차 코드 기준선을 만든다.
- 전체 전투 액션을 한 번에 옮기지 않고, `UActionComponent` 골격과 플레이어 평타 경로만 먼저 이전한다.
- `StateComponent::Type`은 서버에서만 갱신되도록 정리해 클라이언트 로컬 상태 덮어쓰기 문제를 줄인다.

## 기존 문제

- 플레이어 평타는 `ABasePlayer::OnMouseL`에서 `Server -> Reliable Multicast`로 처리되어 소유 클라이언트도 서버 왕복 후에야 몽타주를 보게 되는 구조였다.
- `StateComponent::Type`은 복제 변수지만 `MontageComponent`와 아이템 액션 경로에서 클라이언트도 직접 `ChangeType()`을 호출할 수 있었다.
- 평타, 회피, 스킬, AI 액션의 네트워크 패턴이 서로 달라 이후 액션 추가/수정 시 같은 판단을 반복해야 했다.

## AI 활용 방식

- Codex로 기존 `BasePlayer`, `BaseCharacter`, `StateComponent`, `Item`, `BaseWeapon` 흐름을 검색해 현재 RPC 패턴과 콤보 처리 방식을 확인했다.
- 콤보 윈도우는 기존 `ABaseWeapon::bCanCombo / bSucceed` 흐름을 유지하고, 새 액션 컴포넌트는 요청/검증/복제 진입점만 담당하도록 범위를 줄였다.
- UnrealBuildTool 빌드 로그로 UHT 선언과 C++ 컴파일 성공 여부를 검증했다.

## 구현/수정 내용

- `UActionComponent`를 추가했다.
  - `TryAction(FGameplayTag)` 단일 진입점을 추가했다.
  - 소유 클라이언트는 가능한 경우 즉시 로컬 예측 재생 후 `Server_TryAction`을 보낸다.
  - 서버는 상태/스태미나 조건을 확인한 뒤 `FActiveAction { ActionTag, Sequence }`를 갱신한다.
  - `ActiveAction`은 `COND_SkipOwner`로 복제해 예측한 소유 클라이언트의 중복 재생을 피한다.
- `ABaseCharacter`에 `ActionComponent`를 기본 컴포넌트로 추가했다.
- `ABasePlayer::OnMouseL`을 기존 `ServerOnMouseL -> MulticastOnDefaultAction` 경로 대신 `Action->TryAction(BaseGameplayTags::Ability_DefaultAction)`으로 연결했다.
- 기존 평타용 `ServerOnMouseL`, `MulticastOnDefaultAction` 선언과 구현을 제거했다.
- `StateComponent::Type`을 `ReplicatedUsing=OnRep_Type`으로 전환했다.
- `StateComponent::ChangeType()`은 서버 권위에서만 값을 바꾸도록 막았다.
- `BaseCharacter::EndAction()`은 서버에서만 상태를 `Idle`로 되돌리고, 클라이언트 예측 액션 잠금은 몽타주 종료 시 해제하도록 연결했다.

## 검증 결과

- `SoulLikeEditor Win64 Development` 빌드 성공.
- 최초 빌드는 UBT가 `AppData/Local/UnrealBuildTool` 로그 파일을 갱신하지 못해 샌드박스 권한 오류로 실패했다.
- 권한 상승 후 동일 빌드를 다시 실행했고 UHT, 컴파일, 링크가 모두 성공했다.
- 아직 2인 PIE, NULL 직접 접속, `Net PktLag` 지연 환경 검증은 수행하지 않았다.

## 의사결정

- 이번 단계에서는 스킬, 회피, 스텝백, AI 액션을 옮기지 않았다. 평타 경로에서 예측/복제 패턴을 먼저 검증한 뒤 확장하는 편이 안전하다.
- `AItem`의 기존 `AbilityTag -> FActionData` 맵과 `ABaseWeapon` 콤보 상태를 재사용했다. 새 액션 레이어가 데이터 조회와 콤보 규칙까지 중복 구현하지 않도록 범위를 제한했다.
- 스태미나는 기존 평타와 동일하게 현재 값 검증만 유지했다. 소비 처리는 기존 코드에서도 주석 처리되어 있어 이번 변경에서 새 gameplay 변화로 추가하지 않았다.
