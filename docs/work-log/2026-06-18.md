- 2026-06-12에 추가한 평타 액션 레이어 기준선이 현재 프로젝트에서 빌드 가능한지 다시 확인한다.
- 2인 PIE에서 기본 스폰, 상태 컴포넌트, 장착 아이템 복제 기반이 깨지지 않았는지 확인한다.

## 기존 문제

- 통일 액션 레이어는 `UActionComponent`와 플레이어 평타 경로까지만 1차 적용된 상태였다.
- 회피, 스텝백, 스킬, AI 액션은 아직 기존 `Server -> Reliable Multicast` 경로가 남아 있다.
- 이전 작업 로그에는 2인 PIE, NULL 직접 접속, `Net PktLag` 환경 검증이 아직 수행되지 않은 것으로 남아 있었다.
- `Content/_dev/Level/MainWorld.umap`는 작업 시작 전부터 수정 상태였으므로 이번 검증 범위에서는 건드리지 않았다.

## AI 활용 방식

- Codex로 `StatusComponent`, `ActionComponent`, `BasePlayer`의 스태미나 비용과 평타 진입 경로를 재확인했다.
- UE-MCP로 프로젝트 상태, 빌드, PIE 시작/종료, 런타임 Pawn 및 컴포넌트 상태를 확인했다.
- Git 상태를 함께 확인해 기존 맵 변경과 이번 문서 변경을 분리했다.

## 구현/수정 내용

- 코드 수정은 하지 않았다.
- `AttackCost=-30`, `EvadeCost=-50`처럼 비용 값이 음수로 정의되어 있고 `StatusModify()`가 현재값에 비용을 더하는 구조임을 확인했다.
- 따라서 `Current < -Cost` 형태의 조건은 현재 프로젝트 관례와 맞는 것으로 판단해 변경하지 않았다.
- 2인 PIE에서 `BP_Warrior0`, `BP_Warrior1`이 모두 스폰되는지 확인했다.
- 두 Pawn 모두 `StateComponent.Type=Idle`, `StatusComponent.SP.Current=600`, `EquipComponent.SelectItem` 유효 상태임을 확인했다.
- `ActionComponent.ActiveAction.Sequence=0` 상태로 기본 컴포넌트가 런타임에 존재하는 것을 확인했다.

## 의사결정

- 이번 단계에서는 코드를 고치지 않고 검증 로그를 남기는 데 집중했다.
- 스태미나 조건은 겉보기에는 부호가 어색하지만, 비용을 음수로 저장하는 기존 구조와 맞으므로 수정하지 않았다.
- `OnMouseL()`은 UFUNCTION이 아니어서 UE-MCP `invoke_function`으로 직접 평타 입력을 자동 호출하기 어렵다. 실제 평타/콤보 재생은 수동 입력 또는 별도 테스트 진입점이 필요하다.
