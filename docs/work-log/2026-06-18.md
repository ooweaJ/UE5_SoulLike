- `Content/_dev/Level/MainWorld.umap`는 작업 시작 전부터 수정 상태였으므로 이번 검증 범위에서는 건드리지 않았다.

- Git 상태를 함께 확인해 기존 맵 변경과 이번 문서 변경을 분리했다.

- 이번 단계에서는 코드를 고치지 않고 검증 로그를 남기는 데 집중했다.
- 스태미나 조건은 겉보기에는 부호가 어색하지만, 비용을 음수로 저장하는 기존 구조와 맞으므로 수정하지 않았다.
- `OnMouseL()`은 UFUNCTION이 아니어서 UE-MCP `invoke_function`으로 직접 평타 입력을 자동 호출하기 어렵다. 실제 평타/콤보 재생은 수동 입력 또는 별도 테스트 진입점이 필요하다.

## 별도 프로세스 클라이언트 공격 입력 보정

### 작업 목표

- BAT 별도 프로세스 클라이언트에서 좌클릭 공격이 실행되지 않는 문제의 1차 원인을 줄인다.
- PIE와 별도 프로세스 사이의 Possess/BeginPlay 타이밍 차이로 입력 캐시가 비는 경우를 막는다.

### 원인 판단

- `ABasePlayerController::BeginPlay()`에서 `GetPawn()`을 캐스팅해 `Player`를 캐시하고 있었다.
- 별도 프로세스 클라이언트에서는 `BeginPlay()` 시점에 Pawn possession이 완료되지 않았을 수 있다.
- `OnEvade()`는 입력 시점마다 `GetPawn()`을 다시 확인하지만, `OnMouseL()`은 캐시된 `Player`만 사용해 `Player == nullptr`이면 공격 입력을 조용히 무시할 수 있었다.
- PIE에서는 possession 타이밍이 더 빠르거나 같은 프로세스 환경이라 문제가 드러나지 않았을 가능성이 있다.

### 구현/수정 내용

- `ABasePlayerController::RefreshPlayer()`를 추가해 현재 `GetPawn()` 기준으로 `Player` 캐시를 갱신하도록 했다.
- 좌클릭, 우클릭, 점프, 회피, 쉬프트, Q/E/R 등 기존 `Player` 캐시에 의존하던 입력 핸들러에서 입력 처리 직전 `RefreshPlayer()`를 호출하도록 변경했다.
- 입력 액션 자체나 액션 레이어 로직은 변경하지 않았다.

### 검증 결과

- `Scripts/LaunchNullListenTest.bat`로 클라이언트 좌클릭 평타가 즉시 실행되는지 확인한다.
