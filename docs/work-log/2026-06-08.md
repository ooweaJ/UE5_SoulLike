# 2026-06-08 작업 기록

## 작업 목표

클라이언트에서 캐릭터가 피격될 때 피격 애니메이션이 재생되지 않는 문제를 확인하고, 피격 리액션 몽타주 재생 책임을 더 명확한 구조로 정리한다.

## 기존 문제

- `ABaseCharacter::TakeDamage()`는 서버 권위에서만 데미지와 사망 여부를 처리한다.
- 기존 피격 몽타주 선택 로직인 `HitPlayMontage()`도 `ABaseCharacter`에 있었고, 일반 함수로 서버에서만 호출됐다.
- 따라서 서버에서 피격 판정이 나도 클라이언트에는 피격 몽타주 재생 호출이 전달되지 않을 수 있었다.
- `ABaseCharacter`가 데미지 처리와 데미지 타입별 몽타주 선택까지 함께 맡고 있어 책임 경계가 흐렸다.

## AI 활용 방식

- Codex로 `TakeDamage`, `DamageType`, `PlayAnimMontage`, `NetMulticast`, `MontageComponent` 사용처를 검색했다.
- 현재 공격 액션은 Multicast로 몽타주를 전파하지만, 피격 리액션은 서버 로컬 함수만 호출한다는 차이를 확인했다.
- GAS 도입 대신 현재 프로젝트 구조에 맞춘 단계적 `GAS-lite` 방향을 검토했다.

## 구현/수정 내용

- `ABaseCharacter::HitPlayMontage()`를 제거했다.
- `UMontageComponent`가 데미지 타입을 피격 몽타주 키로 변환하도록 `GetHitReactionMontageKey()`를 추가했다.
- `UMontageComponent::PlayHitReaction()`을 추가해 피격 리액션 재생 진입점을 컴포넌트로 옮겼다.
- `ABaseCharacter::MulticastPlayHitReaction()`을 추가해 복제 Actor에서 피격 리액션 이벤트를 전파하도록 했다.
- `UMontageComponent`는 데미지 타입을 몽타주 키로 변환하고 로컬 몽타주를 재생하는 역할만 맡도록 했다.
- 데미지 타입이 비어 있거나 기본 데미지 타입이면 기존 설계처럼 피격 리액션을 재생하지 않고, Hitstop은 `Hit`, Stun은 `Stun`, Knockback은 `KnockBack`, Knockdown은 `KnockDown` 몽타주 키로 매핑했다.
- `ABaseCharacter::TakeDamage()`는 데미지/사망 판단 후 `MulticastPlayHitReaction()`만 호출하도록 정리했다.
- 이동 입력이 없는 회피 경로인 `ABasePlayer::OnStepBack()`을 Server RPC로 변경하고, `MultiOnStepBack()`에서 `Roll` 몽타주를 재생하도록 했다.

## 검증 결과

- Unreal 5.7 `SoulLikeEditor Win64 Development` 빌드 성공.
- 빌드 중 `StructUtils` 플러그인 deprecated 경고가 있었지만, 이번 변경과 직접 관련된 컴파일 오류는 없었다.
- 기본 데미지까지 `Hit`으로 매핑하면 `Hit` 몽타주의 종료 Notify 구성에 따라 캐릭터가 `Hitted` 상태에 머물러 회피/공격이 막힐 수 있음을 확인하고, 기본 데미지는 리액션 없음으로 복구했다.

## 의사결정

- 당장 GAS를 도입하지 않고, 현재 코드의 컴포넌트 구조를 살려 작은 단위로 책임을 분리하기로 했다.
- 피격 리액션은 단발성 액션 몽타주이므로 이동 애니메이션처럼 AnimBP 상태 머신에만 맡기지 않고, 서버 권위 결정 후 네트워크로 재생 이벤트를 전파하는 구조가 필요하다고 판단했다.
- ActorComponent RPC보다 캐릭터 Actor RPC가 현재 프로젝트의 복제 경계에서 더 명확하므로, 네트워크 전파는 `ABaseCharacter`에 두고 몽타주 선택/재생은 `UMontageComponent`에 둔다.
- 이동 입력 없는 회피는 기존 코드에서 로컬 함수로만 처리되고 몽타주 재생도 없었으므로, 다른 단발 액션과 같이 서버 검증 후 Multicast로 표현을 전파하는 방식으로 맞췄다.
- 장기적으로는 공격, 회피, 스킬도 `CurrentActionTag`와 액션 상태 복제 기반으로 옮기는 것이 좋지만, 이번 작업은 클라이언트 피격 리액션 문제와 책임 분리에만 제한했다.

## 남은 작업

- NULL 직접 접속 또는 PIE 2인 테스트에서 클라이언트 화면에 피격 몽타주가 재생되는지 확인한다.
- 기본 공격, Grux 메테오, Grux 공중 콤보 피격에서 각각 `Hit/Stun/KnockBack/KnockDown` 매핑이 의도대로 보이는지 확인한다.
- 이후 공격/회피/스킬 몽타주도 `AItem` 직접 실행 중심에서 캐릭터 액션 상태 복제 중심으로 옮길지 설계한다.

## Grux 메테오 폭발 이펙트 보정

### 작업 목표

Grux가 던지는 메테오 구체의 충돌 처리를 캐릭터 직접 피격과 바닥 폭발로 분리한다.

### 원인 판단

- `BP_GruxMeteor`에는 `ImpactParticle`과 `N_Meteor`, `N_FlameBlast` 등 Niagara 참조 문자열이 있어 에셋 참조 자체는 들어가 있는 것으로 보인다.
- 기존 `AGruxMeteor::OnHit()`는 캐릭터에 맞아도 바닥에 맞은 것처럼 즉시 폭발하고 삭제되는 구조였다.
- 기존 `AGruxMeteor::OnHit()`는 서버에서 `MultiCast_SpawnImpactEffect()`를 호출한 직후 같은 프레임에 `Destroy()`를 호출했다.
- 복제 Actor가 바로 삭제되면 클라이언트가 Multicast RPC를 받기 전에 삭제 전파가 먼저 처리되어 폭발 이펙트를 놓칠 수 있다.

### 구현/수정 내용

- `AGruxMeteor`에 `bExploded` 가드를 추가해 중복 폭발 처리를 막았다.
- Sphere 충돌에서 Pawn은 Block이 아니라 Overlap으로 받도록 설정했다.
- `OnOverlapBegin()`을 추가해 캐릭터에 닿으면 직접 데미지와 약한 넉백만 적용하고 메테오는 계속 진행하도록 했다.
- 직접 피격 대상은 `DirectHitActors`에 기록해 같은 메테오가 같은 캐릭터에게 중복 직접 데미지를 주지 않도록 했다.
- 바닥/벽 등 월드 충돌은 `Explode()`에서 폭발 범위 데미지와 Multicast 이펙트를 처리하도록 분리했다.
- 충돌 위치는 `Hit.ImpactPoint`를 우선 사용하고, 값이 비어 있으면 Actor 위치를 사용하도록 했다.
- Multicast 이펙트 호출 후 즉시 `Destroy()`하지 않고, 충돌을 끄고 이동을 멈춘 뒤 Actor를 숨기고 `SetLifeSpan(1.f)`로 짧게 지연 삭제하도록 변경했다.

### 검증 결과

- 첫 빌드에서 `FVector_NetQuantize`와 `FVector` 삼항 연산자 타입 불일치로 실패했다.
- `ImpactPoint`를 명시적으로 `FVector`로 변환한 뒤 Unreal 5.7 `SoulLikeEditor Win64 Development` 빌드 성공.
- 캐릭터 오버랩/월드 폭발 분리 후 Unreal 5.7 `SoulLikeEditor Win64 Development` 빌드 성공.

### 남은 확인

- 에디터 재시작 후 캐릭터에 맞을 때 메테오가 사라지지 않고 직접 데미지/넉백만 주는지 확인한다.
- 바닥에 부딪혔을 때 서버/클라이언트 모두 폭발 Niagara와 범위 데미지가 적용되는지 확인한다.
