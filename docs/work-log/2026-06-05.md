# 2026-06-05 작업 기록

## 작업 목표

PIE 창 2개 대신 별도 프로세스로 리슨서버 1개와 클라이언트 1개를 실행해 AI/멀티플레이 동기화를 확인할 수 있는 테스트 방식을 준비한다.

## 기존 문제

- PIE 2인 테스트는 간단하지만, 에디터 내부 실행이라 백그라운드 프레임 저하나 창 포커스 문제로 화면 비교가 어려울 수 있다.
- Steam OSS 전환 전에는 NULL/직접 접속 기준으로 서버-클라이언트 동기화 문제를 먼저 분리해서 확인해야 한다.

## 구현/수정 내용

- `Scripts/LaunchNullListenTest.bat` 생성.
- 첫 번째 프로세스는 `/Game/_dev/Level/MainWorld?listen`으로 리슨서버를 실행한다.
- 두 번째 프로세스는 `127.0.0.1`로 로컬 리슨서버에 접속한다.
- 두 프로세스 모두 `UnrealEditor.exe -game` 방식으로 실행한다.
- Steam이 아니라 NULL/직접 접속 테스트가 되도록 `-nosteam` 옵션을 사용한다.

## 사용 방법

프로젝트 루트에서 다음 파일을 실행한다.

```bat
Scripts\LaunchNullListenTest.bat
```

실행 결과:

- `SoulLike Listen Server`: 리슨서버 창
- `SoulLike Client`: 로컬 클라이언트 창

## 검증 기준

- 두 창이 각각 실행되는지 확인한다.
- 클라이언트가 `127.0.0.1` 리슨서버에 접속되는지 확인한다.
- AI 타이밍 공격 몽타주 속도 변경이 서버/클라이언트 양쪽에서 같은 타이밍으로 보이는지 확인한다.

## 남은 작업

- 실제 bat 실행 후 서버/클라이언트 접속 여부 확인.
- 접속 실패 시 맵 직접 접속 방식과 GameInstance 세션 방식 중 어떤 경로가 필요한지 분리.
- NULL OSS PIE 2인 체크리스트와 별도 프로세스 체크리스트를 함께 정리.

## 백그라운드 FPS 저하 완화 및 Steam OSS 전환 준비

### 작업 목표

별도 프로세스 2개를 띄웠을 때 포커스를 잃은 창의 FPS가 크게 떨어져 동기화 비교가 어려운 문제를 완화한다.

동시에 Steam OSS 전환을 위해 세션 생성/검색 코드가 NULL과 Steam을 자동으로 구분하도록 정리한다.

### 구현/수정 내용

- `DefaultEngine.ini`의 기본 Online Subsystem을 `Steam`으로 변경했다.
- `DefaultEngine.ini` 콘솔 변수에 `t.IdleWhenNotForeground=0`, `r.VSync=0`을 추가했다.
- `Scripts/LaunchNullListenTest.bat` 실행 인자에 백그라운드 FPS 완화용 `-ExecCmds`와 `-NoVSync`를 추가했다.
- `UASGameInstance::RefreshServerList()`가 현재 OSS를 기준으로 `bIsLanQuery`를 설정하도록 변경했다.
- `UASGameInstance::CreateSession()`이 현재 OSS를 기준으로 `bIsLANMatch`와 `bUseLobbiesIfAvailable`을 설정하도록 변경했다.
- `OnJoinSessionComplete()`에서 `OpenLevel` 대신 `ClientTravel`로 세션 접속 주소에 이동하도록 변경했다.
- `Scripts/LaunchSteamMenuTest.bat` 생성.

### 테스트 방식 구분

#### NULL 직접 접속 테스트

```bat
Scripts\LaunchNullListenTest.bat
```

- `-nosteam` 사용
- 리슨서버는 `/Game/_dev/Level/MainWorld?listen`
- 클라이언트는 `127.0.0.1` 직접 접속
- 같은 PC에서 서버/클라이언트 창을 비교하기 위한 빠른 테스트

#### Steam 세션 테스트

```bat
Scripts\LaunchSteamMenuTest.bat
```

- Steam OSS 사용
- 두 창 모두 메뉴 맵에서 시작
- 첫 번째 창에서 Host, 두 번째 창에서 Refresh/Join으로 세션 확인
- 같은 PC와 같은 Steam 계정으로 2개 실행하면 실패할 수 있으므로, 실제 검증은 두 PC 또는 두 Steam 계정이 권장된다.

### 남은 위험

- `Content/_dev/Level/MainWorld.umap`가 별도 수정 상태로 남아 있으나, 이번 작업 범위가 아니므로 커밋하지 않는다.
- Steam 세션은 빌드가 성공해도 실제 Steam 클라이언트 상태, 계정, AppID 480 세션 정책에 따라 런타임 검증이 필요하다.
- 아직 `AItem`/`EquipComponent` 복제 구조가 완성되지 않았으므로, Steam 연결 이후에도 액션 동기화 버그는 별도 수정이 필요하다.
